# Security model

The master key is a 32-byte value loaded from `MCP_MASTER_KEY` (64 hex characters) or `MCP_MASTER_KEY_FILE`. AES-256-GCM encrypts connection configurations, snapshots, prepared SQL/binds and audit payloads with fresh 12-byte nonces and authenticated tags. API tokens and administrator sessions are stored as SHA-256 hashes of 256-bit random values. Administrator passwords use salted scrypt. Tokens are displayed once and have explicit expiry/revocation.

Every MCP call revalidates token identity, connection scope, connection enablement, disabled tools and intersection of token/connection permission flags. Resources use the same read authorization. High-risk SQL is owner/connection-bound and atomically consumed before execution; policy is checked again at execution. Canonical DDL tool disablement also applies to generic execution.

The SQL scanner handles comments, quoted strings/identifiers, dollar quoting and conservative read CTE classification. Unknown/admin/procedural statements fail closed. READ only permits a limited set of built-in function expressions; qualified function calls are denied. PostgreSQL standalone reads additionally run in a database read-only transaction. Protected schemas and out-of-scope qualified relation references are denied. UPDATE/DELETE require a top-level WHERE by default. A WHERE clause does not guarantee narrow effects: review predicates and preview affected rows.

Use dedicated least-privilege application accounts. Policy is not a complete database security sandbox: synonyms, unqualified object resolution, triggers, stored functions, extensions, foreign tables and externally modified schemas can have indirect effects. Do not configure DBA/superuser accounts. Keep allowed schemas narrowly scoped and deny unsafe database privileges independently. Administrators are trusted to configure destination hosts; developers cannot create connections. Restrict outgoing container traffic to approved database hosts.

Sensitive table/column names can be blocked. With blocked columns, SQL wildcards are denied; sampling requires explicit columns. Audit binds/SQL can contain application data and are encrypted at rest, but authorized history/export consumers can read them. Restrict token access accordingly. No raw driver errors or request bodies are logged; external errors contain safe codes only. The server does not expose stored database passwords.

Admin sessions remain in browser memory, use Authorization headers and expire after eight hours. There are no auth cookies. Host/Origin checks, CSP, request size limits and IP rate limiting protect HTTP boundaries. Always use HTTPS; bearer tokens are replayable by anyone possessing them. Configure proxy-side login throttling and administrative network restrictions. MFA/OIDC and tamper-evident audit storage are not implemented.

Do not share the metadata volume between replicas. External database commits and SQLite audit updates cannot be one atomic transaction: an interrupted intent stays pending and requires reconciliation against the database. Do not blindly retry pending writes/migrations. Confirmations enforce two API steps, not proof of a human action; your MCP client's tool approval UX must enforce human approval.
